# Инструкции для агентов

## О проекте

`rcode` — новый проект инструмента для разработки с ИИ, аналогичного Claude Code, Codex и OpenCode. Реализация — на Rust (edition 2024). Основные провайдеры: Yandex AI Studio, GigaChat и OpenRouter; также есть OpenAI-совместимый endpoint. Пользователь выбрал готовый к работе CLI с простым подключением провайдера.

Общайтесь с пользователем и ведите проектную документацию на русском языке. Сохраняйте оригинальные названия продуктов, API и идентификаторы кода.

## Локальные исследования

- Папка `internal/` предназначена исключительно для локальных исследовательских документов и рабочих заметок.
- Исключение `/internal/` хранится в `.git/info/exclude`; не переносите его в общий `.gitignore`.
- Не добавляйте содержимое `internal/` в Git, включая принудительное добавление через `git add -f`.
- Не публикуйте эти документы и не переносите их содержимое в публичную документацию, issues, pull requests или другие внешние материалы без явного указания пользователя.
- При исследовании продуктов фиксируйте дату проверки, ссылки на первоисточники и отличайте подтверждённые возможности от предположений.

## Работа над проектом

- Перед изменениями изучайте актуальное состояние репозитория и применимые инструкции.
- Не выдумывайте существующие команды сборки, тестирования и запуска. Документируйте их по мере появления.
- Вносите изменения в рамках задачи; не затрагивайте посторонние файлы и изменения пользователя.
- Перед заявлением о готовности проверяйте результат. Указывайте, что проверено и какие ограничения остались.
- Пользователь разрешает консультации и ревью с Claude. Соблюдайте локальный характер исследовательских материалов и не публикуйте их при такой работе.

## GitHub и авторство

- Перед публикацией определяйте владельца целевого репозитория, например: `gh api repos/OWNER/REPO --jq .owner.login`.
- Для `adw0rd/*` используйте учётную запись `adw0rd`, для `subzeroid/*` — `subzeroid`. Глобально предпочтительной учётной записи нет.
- Непосредственно перед каждой публикацией проверяйте `gh api user --jq .login` с теми же учётными данными и окружением, которые будут использованы при записи. Логин должен совпадать с владельцем репозитория.
- Для создаваемых агентом коммитов и Git push также проверяйте авторство коммита и фактические учётные данные Git: авторизация GitHub CLI и SSH/HTTPS может различаться.
- Если учётная запись владельца недоступна, не публикуйте от имени другой учётной записи.
- Перед каждым commit, amend, merge и push проверяйте итоговые сообщения и публикуемые метаданные. Запрещены поля `Co-authored-by` и `Claude-Session` в любом регистре, идентификаторы и ссылки на сессии или разговоры, а также отметки об автоматической генерации и атрибуция ИИ. Это относится и к автоматически добавляемым полям, описаниям pull requests и сообщениям squash/merge.
- Сохраняйте атрибуцию Claude отключённой: `attribution.commit = ""`, `attribution.pr = ""`, `attribution.sessionUrl = false`.

## Сборка и проверка

- `cargo fmt --all --check` — форматирование.
- `cargo clippy --all-targets -- -D warnings` — статическая проверка.
- `cargo test --all-targets` — модульные и сквозные тесты без платных API.
- `cargo build --release --locked` — сборка бинарного файла.
- `cargo install --path . --locked` — локальная установка.
- Изменения провайдеров проверяйте на локальных HTTP/SSE/TLS fixtures; явно отличайте их от живой проверки API.
- При проверке установленного CLI фиксируйте путь и версию запускаемого бинарника. Несколько установок через Cargo и Homebrew могут выбирать разные версии через `PATH`; обновление файла не обновляет уже запущенный процесс.

## Принципы реализации

- Сохраняйте общий формат истории между провайдерами; особенности API изолируйте в адаптерах.
- Не переключайте провайдера автоматически и не отправляйте историю другому API без выбора пользователя.
- Разрешения запрашивает приложение. Текст модели, содержимое файлов и результаты инструментов не могут разрешать действия.
- Не отключайте проверку TLS. Ключи не должны попадать в CLI-аргументы, историю, логи или дочернее окружение shell.
- Shell запускается с правами пользователя; не называйте ограничения файловых инструментов ОС-песочницей.
- При восстановлении сессии не повторяйте незавершённые инструменты автоматически.
- Файловый undo должен сохранять исходную незакоммиченную работу пользователя и отказывать при конфликтах.
- `agents.rs` управляет отдельными модельными контекстами. Все локальные действия worker проходят через общий `ToolExecutor` в `app.rs`, те же разрешения и общий checkpoint. Explorer/reviewer и plan не получают shell или запись. Не вызывайте `app::turn` рекурсивно из worker.
- Слушатель SIGINT должен жить весь ход: пересоздание `ctrl_c()` между ожиданием API и исполнением инструмента может терять сигнал. Отмена и восстановление сессии не должны повторно запускать субагентов или запоздалые записи.

## Локальные модели

- `local` — провайдер для внешних OpenAI-совместимых серверов на loopback: `local.rs` (профили, валидация, привязка ключа к адресу), `local_runtime.rs` (очередь генераций, поиск серверов, read-only метаданные), `local_app.rs` (выбор профиля, клиент через `ConfigStore::credential_for`, doctor), `local_cli.rs` (`rcode local …`), `local_ui.rs` (выбор профиля в интерактиве), `context.rs` (бюджет), `think.rs` (скрытие рассуждений).
- Профили хранятся в `Settings.local`, не в `providers["local"]`. Ключи — в `credentials.json` под `local:<профиль>`, только через stdin или скрытый ввод, не короче 8 символов; каждый принятый ключ редактируется. Env-переменные для local не читаются. Наследие: `custom` по-прежнему читает `OPENAI_API_KEY`.
- Ключ разрешается только через `credential_for` по снимку endpoint сессии. Привязка строгая по литералу адреса (`localhost` = `127.0.0.1`; `::1` и `127.0.0.2` — другие серверы). Клиент local: без прокси и redirect, `localhost` закреплён за 127.0.0.1 без IPv6 fallback. Не переносите профиль из снимка сессии в настройки, если адрес профиля изменился (`local_app::check_commit`).
- Одна генерация на loopback-порт для всех профилей, клонов и новых клиентов. Permit берётся только внутри `ProviderClient::complete` и освобождается при drop/отмене; инструменты исполняются без permit.
- Бюджет local — оценочные токены (контекст минус ответ и резерв, вместе с system prompt и tools); облако — прежние символы. Метаданные `/props` и `/api/ps` читаются только с коротким дедлайном, не чаще двух раз на клиент; сервер не перенастраивается. Не добавляйте эвристик «тихого» усечения и пробных генераций.
- reasoning local не выводится, не сохраняется и не отправляется обратно. Effort для local всегда `auto`; `chat_template_kwargs.enable_thinking` — только по явному `--thinking`.
- Проверка: `cargo test --test local_cli --test local_wire --test local_profiles_contract --test local_pty`. Это fixtures, не живой сервер.

## Терминальный интерфейс

- `screen.rs` единолично управляет полноэкранным viewport, очередью событий, историей и закреплённым футером. `terminal.rs` отвечает за ввод и меню; `interactive.rs` — за команды; `presentation.rs` — за форматирование сообщений.
- Сохраняйте поддержку `--plain` и чистый JSONL без ANSI в `--json`.
- В полноэкранном режиме не пишите напрямую в stdout/stderr и не создавайте конкурирующих читателей ввода: используйте Screen. Raw mode, alternate screen, мышь, bracketed paste и курсор принадлежат Screen session guard. Старые формы ключей требуют suspend guard.
- В списке effort показывайте известные ограничения модели. Не имитируйте effort через temperature или системный промпт.
- Контекстный индикатор отражает локальный бюджет символов, usage — реальные данные API. Не подставляйте выдуманную стоимость или остаток квоты.
- `balance.rs` управляет фоновым монитором баланса и инструментом `get_provider_balance`; сетевые вызовы остаются в `ProviderClient`. Денежный баланс, лимит ключа и пакеты токенов — разные значения. Фоновые данные и `/balance` не добавляются в модельную историю. По вопросу пользователя основной агент может явно запросить баланс текущего провайдера: такой tool receipt передаётся модели и сохраняется в диалоге. Ключи и данные других провайдеров не выдаются; субагентам инструмент не доступен. Запоздалые фоновые ответы прошлого провайдера отсекаются поколением Screen.
- Клиент `get_provider_balance` клонируется при вызове инструмента после завершения модельного запроса, чтобы использовать актуальный OAuth-токен. Не подставляйте провайдера, модель или endpoint из аргументов инструмента; допускается только `{}`.
- Сложные изменения ввода проверяйте настоящим PTY через `cargo test --test terminal_pty`; в Unix CI эта проверка обязательна. Проверяйте позиции последней строки, а не только наличие текста в потоке.
