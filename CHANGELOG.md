# История изменений

## Не выпущено

- Добавлена опциональная OS-песочница для команд shell модели (`run_command`, `start_command`, `handoff_command`, субагенты `worker`, этап `--final-review-repair`) на macOS (`Seatbelt` `deny default`) и Linux (`Landlock ABI ≥ 3`, `CLOSE_RANGE_CLOEXEC` и `seccomp-bpf` против `io_uring_*`, `chown*`/`*xattr*` и именованных/абстрактных `AF_UNIX`): флаги `--sandbox off|workspace-write|read-only` и `--sandbox-network on|off`, команды `rcode sandbox [status|mode|network]` и интерактивный `/sandbox` с сохранением на проект в `permissions.json`, изолированный `0700` `TMPDIR` на каждое задание с очисткой после подтверждённого завершения процесса, поддержка внешних `git worktree` только при взаимно проверенном backlink и fail-closed отказ на неподдерживаемых ОС и старых ядрах без отката к запуску без изоляции.
- Файловые инструменты `write_file` и `edit_file` обновляют снимок чтения (`read_snapshots`) текущего актора проверенной опубликованной версией файла после успешного коммита, устраняя холостые циклы принудительного повторного `read_file` между последовательными правками одного актора при сохранении защиты от внешних изменений и изоляции между субагентами.
- В описании `edit_file` явно указано не копировать префиксы номеров строк `N\t` из вывода `read_file`.

## 0.10.0 — 2026-11-13

- Межсессионная файловая память (`read_memory`, `write_memory`, `rcode memory …`, `/memory`): приватные Markdown-заметки `project/<slug>` и `global/<slug>` в `RCODE_HOME/memory` (`0700`/`0600`, без следования симлинкам, сериализация под `memory.lock`), бюджет `<rcode_memory_index>` (до 4 000 символов в облаке и до 4 % бюджета контекста `local`), обязательное diff-подтверждение оператора во всех `ApprovalMode` (с явным opt-in `rcode memory auto-write`), двухуровневая защита от сохранения известных и эвристических секретов до подстановки `[REDACTED]`, история ревизий (`.revisions/`, ротация 5), CAS-откат (`undo`) с защитой ручных правок и полное отключение в `rcode eval`.
- Инструмент `ask_user` для уточнения неоднозначных развилок прямо во время хода в интерактивном терминале (включая `/plan`): 1–3 кратких вопроса по 2–4 варианта с рекомендуемым первым, встроенный ввод «Свой вариант…», пропуск по `Esc` без подстановки ответа по умолчанию и неблокирующий опрос в `--plain`. Ответы проходят редактирование известных секретов, учитываются в финальном ревью как уточнения задачи и не заменяют подтверждения разрешений; восстановленные в `rcode exec` сессии сохраняют совместимость схемы.
- Сокращены описания инструментов и правила системного промпта для экономии контекста локальных моделей и уменьшения лишних вызовов поиска, повторного чтения файлов и запуска субагентов на простых задачах.
- Добавлен изолированный TODO API suite в `rcode eval`: нативный GigaChat host relay с host-only credentials, eval protocol 2 (несовместим с protocol 1), receipt policy/required skills, offline Docker controls без model inference, сохранение снимков `/workspace` (`--snapshots`) и fail-closed локальная диагностика формальных нарушений (`--diagnostics`).
- Видимое задание TODO API документирует весь существующий HTTP oracle-контракт, включая `/health`, CRUD-статусы, форму ответов и validation errors; добавлен regression-тест точных строк prompt-контракта.
- Отмена хода перед фактическим запуском `run_command` классифицируется как прерывание и сохраняет код завершения 130.

## 0.9.3 — 2026-11-08

- Добавлен режим финального ревью с доработкой и проверкой (`rcode --final-review-repair …` и `/final-review repair`): после read-only ревью выбранной моделью основная модель получает замечания как недоверенные данные (`<untrusted_final_review>`), может выполнить до 4 шагов (до 8 вызовов инструментов без субагентов и фонового handoff) для точечной проверки и возвращает исправленный ответ (`primary_repaired`) с фиксируемым статусом верификации (`verified_scoped`, `failed`, `not_run`, `unknown`).
- При явном выборе скилла (`/skill ID` или `/ID` в начале строки) rcode загружает первую страницу `SKILL.md` через `load_skill` до первого запроса к модели; при ошибке чтения скилла запрос к API не отправляется.
- На Linux и macOS файловый undo использует ограниченный приватный WAL: после сбоя он не повторяет записи автоматически, а `/undo` отказывает при внешних изменениях. На Windows сохраняется прежнее best-effort поведение.
- Исправлено направление стрелок в подтверждении действий; выбранная кнопка выделяется фоном, а shell-команда показывается блоком кода с настоящими переносами строк.
- Успешные и ошибочные результаты `run_command` показываются компактно. Ctrl+O раскрывает сохранённый stdout/stderr в полноэкранном интерфейсе и снова сворачивает его.
- Перед финальным резюме rcode останавливает workers и собирает их результаты; субагенты больше не исполняют инструменты во время составления итога.
- Пустой ответ или вызов инструмента вместо финального резюме отклоняется без сохранения аргументов в историю. При ошибке резюме видна причина остановки хода; Ctrl+C сохраняет код отмены 130.
- Статистика сессии учитывает кэшированные токены финального запроса.
- Веб-поиск без настройки объясняет отсутствие результатов и предлагает Yandex Search API, Brave Search API или Tavily со скрытым вводом ключа. Документированный флаг `websearch key --stdin` работает вместе с прежним `--api-key-stdin`.
- Поисковые ключи привязаны к провайдеру (`websearch:<имя>`); при смене API старый ключ и специфичные настройки сбрасываются. Прежний общий ключ `websearch` больше не отправляется: его нужно повторно ввести для выбранного API. Отражённые в ответах и URL ключи скрываются до передачи результатов модели.

## 0.9.2 — 2026-11-03

- Лимит шагов больше не обрывает ход молча: финальный запрос без инструментов требует у модели текстовое резюме — что сделано, что осталось, что делать дальше (как MAX_STEPS_PROMPT в opencode); JSONL: `done` с `summary: true`.
- Циклы повторов: счётчик вызова растёт даже при слегка различающихся результатах (чередование усечённых поисков — тоже цикл, стоп с 8 вызовов); подсказка о повторе попадает в уведомления и переживает автокомпакт; при зацикливании в интерактиве пользователь получает панель «Прервать и получить резюме / Продолжить ход» (по образцу doom_loop opencode), в exec — остановка с резюме.

## 0.9.1 — 2026-11-02

- Скрипты и интерпретаторы анализируются на деструктивные операции: `bash скрипт.sh`, `./setup`, `python/node/bun файл`, `sh -c '...'`, `npm/bun run` и Makefile — содержимое сканируется на `rm`/`rmdir`/`shred`/`rmtree`/`rimraf`/`git clean -f`/`find -delete`/`dd`; найденное делает команду удалением без гранта (цели внутри скрипта неизвестны). Полная гарантия — только OS-песочница (в планах).
- Удаления файлов спрашивают подтверждение всегда, даже в full-access (`rm`, `rmdir`, `unlink`, `shred`, `git clean -f`, `find -delete`); в панели — грант «Разрешить удаления в <каталог> всегда». Разрушительные операции с носителями и данными rcode/дома (`dd`, `mkfs`, `rm -rf ~`, `mv` поверх данных rcode) — подтверждение каждый раз без гранта.
- Автобэкапы критичных файлов состояния: `config.json`, `permissions.json`, `skills.json` перед перезаписью копируются в `RCODE_HOME/backups/` (ротация 5 копий); `credentials.json` не бэкапируется — ключи живут только в одном файле.
- Веб-поиск: если поиск не настроен, интерактивный rcode показывает панель выбора провайдера прямо во время хода (Esc — пропустить); ключ вводится позже через `/websearch` или `rcode websearch key --stdin`. Добавлена команда `/websearch` (провайдер и ключ скрытым вводом).
- Панель выбора в полноэкранном режиме во время хода: новая клавиатурная панель Screen (`Esc` — отмена), stdin-промпты во время хода не используются.

## 0.9.0 — 2026-11-02

- Футер: в статус-строке справа — путь проекта (укорачивается с хвостом) рядом с версией.
- Модель для чтения изображений: дополнение. Проверено живьём: GigaChat-2-Max принимает изображения сам; модели Yandex AI Studio молча игнорируют изображения (ошибки нет, `prompt_tokens` без картинки), поэтому Yandex теперь считается не принимающим изображения — скрины уходят читателю `/vision` или превращаются в понятную ошибку.
- Модель для чтения изображений: если основная модель не принимает картинки (local без `--vision`, модель OpenRouter без изображений в `input_modalities`), rcode отправляет вложение вспомогательной модели и передаёт основной текстовую расшифровку. Выбор — команда `/vision` по аналогии с `/model`; настройка в `config.json` (`vision.provider`, `vision.model`), ключи общие с провайдером. JSONL: событие `vision`.
- Установка скиллов изнутри сессии: модель может запустить `rcode skills install …` через shell — согласие пользователя даёт обычная панель подтверждения команды; блокировка `RCODE_MODEL_SHELL` осталась только для ключей поиска.
- Разрешения: в диалоге shell-команды появился вариант «Разрешить похожие» — первый токен команды сохраняется в `permissions.json` проекта и больше не запрашивается.

## 0.8.0 — 2026-11-01

- Инструмент `web_search`: веб-поиск через API на выбор — Yandex Search API (Yandex Cloud), Brave Search API или Tavily. Ключ хранится в `credentials.json` (`rcode websearch provider|key|status|clear`), при первом вызове без настройки интерактивный rcode предлагает подключить провайдера. Поиск — только чтение, без подтверждений.
- Инструмент `web_fetch`: модель может открыть веб-страницу по http(s)-URL и получить текст (HTML приводится к тексту). Только чтение, без ключей rcode и подтверждений; редиректы ограничены пятью, ответ укорачивается до ~50 тыс. символов, не-текстовые ответы отклоняются.
- Скиллы в формате SKILL.md: каталог «id — описание» в системном промпте, полный текст по запросу через инструмент `load_skill` со страницами для длинных файлов. Свои скиллы — `RCODE_HOME/skills` и `.rcode/skills`; наборы ставятся командой `rcode skills install` (git clone `--depth 1` или копирование каталога) с атомарным `update`, `check`, `remove`, `enable/disable`; чужие каталоги подключаются `rcode skills link` без копирования. Git запускается с очищенным окружением, `http://`, `git://`, `ext::` и адреса с userinfo отклоняются; hooks и скрипты наборов не исполняются, права не меняются.
- Пользовательские команды: Markdown-файлы в `RCODE_HOME/commands` и `.rcode/commands` (`git/pr.md` → `/git:pr`), подстановка `$ARGUMENTS`, `$1…$9`, `$$`; меню, Tab-дополнение и `/help` учитывают их. Имена встроенных команд перекрыть нельзя; `!`-shell и `@файл` не исполняются.
- Команды `/skills`, `/skill ID запрос`, `/context` с учётом каталога; JSONL: события `skill`, `skill_source`, `command`, `skills_toggled`, у новых событий поле `version: 1`.
- Каталог скиллов учитывается в бюджете контекста (облако — символы, local — оценочные токены); без скиллов промпт и бюджет не меняются. Субагенты каталог и `load_skill` не получают.

## 0.7.0 — 2026-10-31

- Провайдер `local` для запущенных вами серверов Ollama, llama.cpp, MLX и LM Studio на 127.0.0.1: несколько именованных профилей, поиск серверов на стандартных портах, `/provider` → `local` и команды `rcode local discover|list|add|use|key|remove`, флаг `--profile`.
- Ключ локального сервера необязателен, вводится только через stdin или скрытый ввод и отправляется только на адрес своего профиля. Ключи облачных провайдеров из окружения на локальный сервер не уходят.
- Одна генерация на локальный сервер, включая субагентов. Бюджет контекста local в оценочных токенах с учётом фактического контекста llama.cpp и Ollama; футер показывает оценку в токенах.
- Рассуждения локальных моделей не показываются и не сохраняются в истории.
- Сокращённые receipts local сохраняют статус и ключевые поля результата: `exit_code`, `error`, `path` и другие; denied/interrupted/unknown не превращаются в успех. Идентичные повторные read-only наблюдения получают понятное сообщение и останавливают ход вместо бесконечного цикла чтений.
- JSONL: новое событие `warning`; `context_compacted` для local содержит `unit: "estimated_tokens"` и поля `before`, `after`, `saved`. Формат событий облачных провайдеров не изменился.
- Конфигурация с активным `local` и сессии local не читаются версиями 0.6.2 и старше.
