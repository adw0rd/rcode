# Участие в разработке

Понадобится Rust 1.88+. Клонируйте репозиторий и установите локальную сборку:

```sh
git clone https://github.com/adw0rd/rcode.git
cd rcode
cargo install --path . --locked
```

Перед отправкой изменений выполните:

```sh
cargo fmt --all --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --all-targets --locked
cargo build --release --locked
```

Обычные проверки не требуют API-ключей. Терминальные проверки на Linux/macOS используют Python 3 со стандартными модулями PTY, TLS-проверки — OpenSSL. Изменения адаптеров проверяйте локальными HTTP/SSE/TLS-серверами; при проверке живого API явно указывайте модель и фактический результат.

Проверка настоящих Superpowers без сети и модели:

```sh
cargo test --test skills_activation real_superpowers
```

Используется неизменённый MIT-срез upstream: пять скиллов и их supporting files, версия и SHA-256 сохранены в `tests/fixtures/superpowers-upstream/UPSTREAM.json`. Эта проверка покрывает загрузку, ресурсы, сопоставление инструментов и сохранение plan permissions; она не оценивает качество решения модели.

Для живой проверки на уже запущенной локальной модели (macOS/Linux):

```sh
RCODE_SUPERPOWERS_LIVE=1 \
RCODE_BIN="$PWD/target/release/rcode" \
RCODE_LIVE_MODEL='ID_ЛОКАЛЬНОЙ_МОДЕЛИ' \
python3 tests/superpowers_live.py -v
```

По умолчанию используется `http://127.0.0.1:8080/v1` и бюджет 131072 токена; при необходимости задайте `RCODE_LIVE_BASE_URL` и `RCODE_LIVE_CONTEXT` согласно вашему серверу. Тесты не запускают сервер и не отправляют запросы в облако. Для каждого сценария создаются отдельные HOME, RCODE_HOME и Git-проект без ключей пользователя; дедлайн одного хода — 480 секунд. Проверяются реальный RED → исправление → GREEN, plan без записи/shell и вызов отдельного reviewer с получением результата. Зелёный transport-тест не заменяет этот прогон. Для сохранения приватных JSONL receipts задайте `RCODE_LIVE_ARTIFACT_DIR` вне публикуемого дерева; журналы могут содержать локальные пути и идентификаторы сессий, их нельзя добавлять в Git.

В issue с ошибкой укажите `rcode --version`, ОС, провайдера, модель и шаги воспроизведения. Удалите ключи, персональные данные и чувствительные фрагменты проекта из логов и скриншотов.

В pull request опишите, что изменилось и как это проверено. Сохраняйте русский язык интерфейса и документации, общий формат сессий между провайдерами и поддержку `--plain`/JSONL. Подробные правила находятся в [AGENTS.md](AGENTS.md).
