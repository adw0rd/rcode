# rcode

**Терминальный ИИ-агент для разработки с Yandex AI Studio, GigaChat и OpenRouter.**

[![Проверки](https://github.com/adw0rd/rcode/actions/workflows/ci.yml/badge.svg)](https://github.com/adw0rd/rcode/actions/workflows/ci.yml)
![Rust 1.88+](https://img.shields.io/badge/Rust-1.88%2B-000000?logo=rust)
[![Лицензия MIT](https://img.shields.io/badge/Лицензия-MIT-blue.svg)](LICENSE)

Написан на Rust. Читает проект, меняет файлы, запускает команды и делегирует задачи субагентам. Провайдера и модель выбираете вы; переключиться можно прямо во время работы. Интерфейс и команды справки — на русском языке.

**Ранняя рабочая версия — 0.4.4.** Для подключения нужен собственный API-ключ и доступный баланс или квота провайдера. Возможности агента зависят от выбранной модели.

[Быстрый старт](#быстрый-старт) · [Провайдеры](#провайдеры) · [Команды](#команды-и-интерфейс) · [Субагенты](#субагенты) · [Разработка](#разработка)

## Что умеет

- Исследовать код, искать по проекту, читать, создавать и редактировать файлы.
- Выполнять команды и тесты с разрешения пользователя.
- Работать с каталогами моделей и глубиной рассуждений через `/model` и `/effort`.
- Делегировать работу субагентам: исследователю, исполнителю и ревьюеру.
- Сохранять диалог, восстанавливать сессии и отменять файловые правки.
- Показывать потоковый ответ, историю и закреплённый футер с моделью, разрешениями и токенами.
- Выполнять отдельные задачи через `exec` и выдавать события JSONL для автоматизации.

## Быстрый старт

Понадобятся Git, Rust **1.88 или новее** и доступ к репозиторию.

```sh
git clone https://github.com/adw0rd/rcode.git
cd rcode
cargo install --path . --locked
rcode
```

Если репозиторий уже скачан, начните с `cargo install --path . --locked` в его корне. После установки `rcode` можно запускать из папки любого проекта.

```sh
rcode -C /путь/к/проекту
# Внутри CLI напишите, например:
# Найди причину падающего теста, исправь её и проверь результат.
```

При первом запуске мастер предложит провайдера, покажет ссылку на получение ключа и запросит его скрытым вводом. После авторизации появится список моделей из API: стрелки выбирают модель, ввод текста ищет по названию или ID, Enter подтверждает, Esc отменяет подключение. В `--plain` выбор выполняется по номеру. Есть отдельный пункт для ручного ID, в том числе при недоступности каталога; такой выбор не подтверждает доступ к модели. При отмене новый ключ и настройки не сохраняются. Затем можно написать задачу обычным текстом. Повторно настроить подключение:

```sh
rcode connect yandex
rcode connect gigachat
rcode connect openrouter
```

## Провайдеры

| Подключение | Что понадобится | Настройка |
| --- | --- | --- |
| Yandex AI Studio | Секретный API-ключ и ID каталога | `rcode connect yandex` |
| GigaChat | Authorization Key и Scope из Sber Studio | `rcode connect gigachat` |
| OpenRouter | API-ключ OpenRouter | `rcode connect openrouter` |
| Свой API | Адрес OpenAI-совместимого сервера и ключ | `rcode connect custom` |

### Yandex AI Studio

Для Yandex введите **«Секретный ключ»** из окна создания API-ключа AI Studio в поле скрытого ввода. **«Идентификатор API-ключа»** из того же окна `rcode` не использует. Отдельно нужен **ID каталога (Folder ID)**, в котором создан ключ: выберите этот каталог в [консоли Yandex Cloud](https://console.yandex.cloud/) и скопируйте ID под его названием или из адреса `https://console.yandex.cloud/folders/<ID каталога>`. Подробности — в [инструкции Яндекса](https://yandex.cloud/ru/docs/resource-manager/operations/folder/get-id). В поле каталога также можно вставить полный URI `gpt://folder/model/version`: мастер извлечёт каталог и предложит эту модель в списке. Обычный вход в Яндекс и подписка на чат не заменяют доступ к API.

Провайдер `yandex` использует Yandex AI Studio: по тому же ключу можно выбирать YandexGPT и другие модели из его каталога. Для нового подключения предлагается `deepseek-v4.1-flash/latest`, доступный через API Яндекса; сохранённая ранее модель при обновлении не меняется. Посмотреть свой каталог можно командой `rcode models --provider yandex`, выбрать модель — через `/model`.

### GigaChat

Для GigaChat нужен **Authorization Key** из Sber Studio; Client ID отдельно вводить не требуется. Оставьте `Scope` равным выданному в кабинете значению, например `GIGACHAT_API_PERS`, и введите Authorization Key скрыто. [CA-сертификат Минцифры](https://developers.sber.ru/docs/ru/gigachat/certificates) скачивается автоматически при первом запросе к официальным адресам GigaChat, проверяется по закреплённому SHA-256 и сохраняется в `certificates/` внутри каталога настроек `rcode`. Следующие запуски используют кэш. Сертификат применяется только к официальным адресам GigaChat; системное хранилище и другие провайдеры не меняются, проверка TLS остаётся включённой. Временный access token CLI получает и обновляет самостоятельно.

Для корпоративного прокси или собственного CA укажите `rcode --ca-file /path/to/ca.pem connect gigachat`. Явно заданный файл имеет приоритет над автоматическим сертификатом. При недоступности сайта сертификатов первый запуск предложит повторить подключение или указать свой файл; проверенный кэш работает без повторной загрузки.

### OpenRouter и свой API

Для OpenRouter мастер запрашивает API-ключ. Для своего OpenAI-совместимого сервера укажите адрес API и ключ; сервер должен поддерживать текстовый диалог и вызов инструментов.

Мастер показывает ссылки на [Yandex AI Studio](https://aistudio.yandex.cloud/), [GigaChat API](https://developers.sber.ru/studio/) и [OpenRouter](https://openrouter.ai/settings/keys). В этой версии используется ввод ключа, браузерный OAuth для личных аккаунтов не реализован.

Ключ можно передать через окружение, например `OPENROUTER_API_KEY`, затем сразу запустить:

```sh
rcode --provider openrouter
rcode --provider openrouter --model qwen/qwen3-coder
rcode --provider yandex --folder-id YOUR_FOLDER_ID
rcode --provider yandex --model deepseek-v4.1-flash/latest
```

Доступность конкретной модели и вызова инструментов зависит от провайдера. `rcode models --provider openrouter` показывает актуальные идентификаторы. DeepSeek и Qwen можно выбирать через OpenRouter и, при наличии в своём каталоге, через Yandex AI Studio; отдельных адаптеров для их прямых API пока нет.

## Работа с проектом

```sh
rcode -C /path/to/project
rcode -C /path/to/project "Разберись в проекте и предложи улучшение"
rcode --resume latest
rcode --resume latest --compact exec "Продолжи работу после сокращения истории"
rcode sessions
```

Агент умеет перечислять файлы, искать по содержимому, читать файлы, создавать и редактировать их, запускать команды. Учитывает `.gitignore` и `.git/info/exclude`. Загружает корневой `AGENTS.md`. По умолчанию перед изменениями показывает diff и запрашивает разрешение; shell требует отдельного разрешения. Команда shell показывается в JSON-записи, где переводы строк и невидимые символы видны явно. Для ручного подтверждения слишком длинную команду нужно разбить на короткие шаги.

Интерактивный режим занимает всё окно терминала. История и ответы находятся в основной области, поле ввода закреплено снизу, а последние две строки отведены под модель, провайдера, effort, разрешения, токены и индикатор контекста. Футер остаётся видимым во время запроса, работы инструментов, подтверждений и выбора настроек. При выходе восстанавливается исходный экран терминала.

История прокручивается колесом мыши или PageUp/PageDown; Ctrl+Home переходит в начало, Ctrl+End возвращает к новым сообщениям. При чтении старых строк входящий ответ не сдвигает текущий просмотр. Новый отправленный запрос возвращает к концу истории. Во время работы Esc или Ctrl+C прерывают запрос.

## Команды и интерфейс

Нажмите `/`, чтобы открыть меню команд. В меню моделей доступны поиск, стрелки, PgUp/PgDn, Enter и Esc. Вставка нескольких строк сохраняет переводы строк; Alt+Enter добавляет новую строку, Enter отправляет запрос. Ctrl+P/N возвращает предыдущие запросы, Tab дополняет команду.

| Команда | Действие |
| --- | --- |
| `/model` | Выбрать модель текущего провайдера из каталога API |
| `/model qwen/qwen3-coder` | Указать ID модели напрямую |
| `/model openrouter z-ai/glm-5.3-flash` | Явно сменить провайдера и модель |
| `/provider` | Выбрать провайдера; при необходимости настроить ключ |
| `/effort` или `/effort high` | Выбрать глубину рассуждений |
| `/permissions` | Подтверждения `ask` или файловые правки `auto-edit` |
| `/resume` | Выбрать сохранённую сессию этой папки |
| `/agents` или `/agents ID` | Задачи субагентов, их результаты и токены; ID можно сократить до однозначного префикса |
| `/connect [провайдер]` | Настроить доступ (`/login` — синоним) |
| `/status` | Модель, effort, разрешения и текущая сессия |
| `/context` | Локальный бюджет истории и известные параметры API |
| `/cost` | Токены за сессию и последняя сообщённая API стоимость |
| `/plan [on\|off]` | Исследование без изменений и shell |
| `/diff`, `/undo` | Посмотреть или отменить файловые правки последнего хода |
| `/compact` | Сократить историю и крупные результаты инструментов |
| `/clear` или `/new` | Новый диалог; старый остаётся доступен |
| `/help`, `/exit` | Справка и выход |

`/effort` использует данные выбранной модели, когда API их публикует. Неподдерживаемые уровни не предлагаются; при неизвестной поддержке показано предупреждение. `auto` оставляет настройки провайдера по умолчанию. Выбранный уровень передаётся в настоящий API-запрос и сохраняется вместе с моделью. При смене модели effort сбрасывается в `auto`. Поддержка рассуждений зависит от модели — см. [OpenRouter](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens), [Yandex AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/chain-of-thought).

Индикатор контекста показывает **локальный лимит CLI — 180 000 символов**. Это не баланс аккаунта и не точная токенизация. Токены берутся из ответа API; стоимость отображается только если API её сообщает. `/permissions` действует в текущей сессии и не разрешает shell автоматически.

```sh
rcode --provider openrouter --effort high
rcode --plain                        # обычная строка без панелей и анимации
```

Ctrl+C прерывает запрос или команду; в поле ввода сначала очищает набранный текст. Повторный Ctrl+C на пустом вводе завершает работу. Esc закрывает меню, Ctrl+D на пустом вводе — выход. Незавершённые инструменты не повторяются при восстановлении. Сессия привязана к рабочей папке. Переключение провайдера передаёт ему сохранённую историю только после явного выбора; автоматического переключения на другой API нет.

Файловые инструменты принимают относительные и абсолютные пути внутри рабочего проекта. Для создания проекта во внешней папке, например `/tmp/godot_game`, агент использует `run_command` с обычным подтверждением shell; `auto-edit` само по себе его не разрешает. Ошибка `outside_workspace` сообщает модели этот маршрут. Если модель три шага подряд повторяет такую ошибку без успешных действий, ход останавливается с неполным результатом. Ignore, защита секретов и запрет symlink сохраняются; изменения shell не входят в `/undo`.

## Субагенты

Основной агент может делегировать независимые части задачи. Можно попросить об этом обычным текстом, например: «Поручи одному субагенту изучить код, второму — проверить тесты, затем собери результаты». У каждого субагента отдельный контекст и тот же выбранный провайдер и модель; история автоматически не отправляется другому API.

- `explorer` изучает файлы и ищет информацию в проекте.
- `reviewer` проверяет код и предлагает исправления.
- `worker` выполняет работу, в том числе меняет файлы и запускает команды в рамках текущих разрешений.

`explorer` и `reviewer` используют только чтение и поиск. `worker` получает те же проверки доступа, что основной агент: `ask` требует подтверждения изменений, `auto-edit` разрешает файловые правки, shell разрешается отдельно. Все файловые инструменты проходят через общее исполнение и `/undo`; shell-изменения отменяются вручную. В режиме плана все субагенты работают только на чтение.

Доступно до трёх одновременных субагентов и шести запусков за ход. Новых субагентов они не создают. Основная модель использует инструменты `spawn_agent`, `wait_agent`, `list_agents` и `close_agent`, чтобы назначать задачи, получать результаты и отменять работу. Ctrl+C отменяет основной запрос и дочерние задачи. При восстановлении сессии незавершённые субагенты отмечаются как прерванные и не запускаются повторно.

События работы видны в истории терминала. `/agents` показывает последние 24 задачи с состояниями, результатами и фактическим usage; `/agents ID` открывает подробности. Токены дочерних запросов входят в общий расход сессии.

## Выполнение одной задачи

```sh
rcode --provider openrouter exec "Изучи проект и объясни точку входа"
rcode exec --approval-mode auto-edit "Исправь ошибку в обработке дат"
rcode exec --approval-mode auto-edit --allow-shell "Исправь ошибку и запусти тесты"
rcode exec --plan "Составь план обновления зависимостей"
rcode exec --json --max-steps 20 "Найди причину ошибки"
```

`auto-edit` разрешает файловые правки. `--allow-shell` отдельно разрешает команды с правами текущего пользователя. Без терминала действия, требующие подтверждения, отклоняются. В `--json` stdout содержит только события JSONL с `version: 1`: `start`, `text`, `tool_start`, `tool_result`, `usage`, `agent_update`, `preview`, `done`, `error` и события справочных команд.

После ошибки инструмента CLI даёт модели один дополнительный шаг для проверки причины и продолжения задачи. Отказ в разрешении не повторяется. Если последняя ошибка осталась нерешённой, ход считается незавершённым.

Коды завершения: `0` — ход завершён, `1` — действие отклонено, осталась ошибка или достигнут лимит, `2` — настройки/аргументы, `3` — авторизация API, `4` — ошибка транспорта/протокола API, `130` — прерывание. Завершение хода само по себе не гарантирует правильность кода: проверяйте diff и тесты.

## Настройки и данные

```sh
rcode doctor
rcode doctor --check --provider openrouter
rcode models --provider gigachat
rcode --provider custom --base-url http://localhost:11434/v1 --model YOUR_MODEL
```

`doctor` показывает расположение настроек и источник ключа без его значения. `--check` дополнительно обращается к API. `RCODE_HOME` позволяет выбрать каталог данных; он должен находиться вне рабочей папки.

Ключи хранятся отдельно в `credentials.json`, настройки — в `config.json`, сессии и checkpoints — в `sessions/`. На Unix новые каталоги получают права `0700`, файлы — `0600`. Это локальные файлы, без шифрования; системное хранилище секретов пока не используется. Сессии содержат запросы, ответы и прочитанные фрагменты проекта.

Переменные окружения имеют приоритет над сохранённым ключом:

| Провайдер | Переменные в порядке приоритета |
| --- | --- |
| Yandex | `RCODE_YANDEX_API_KEY`, `YANDEX_API_KEY` |
| GigaChat | `RCODE_GIGACHAT_AUTH_KEY`, `GIGACHAT_AUTH_KEY`, `GIGACHAT_CREDENTIALS` |
| OpenRouter | `RCODE_OPENROUTER_API_KEY`, `OPENROUTER_API_KEY` |
| Свой API | `RCODE_CUSTOM_API_KEY`, `OPENAI_API_KEY` |

## Границы ранней версии

- Это локальный агент с доступом к выбранному проекту. Shell работает с правами пользователя: разрешённая команда может обращаться к данным за пределами проекта. ОС-песочницы пока нет. В shell не наследуются ключи API из окружения, но доступ к файловой системе остаётся.
- Файловые инструменты блокируют `.git`, `.env*`, распространённые файлы ключей, игнорируемые пути и символьные ссылки. Читать бинарные файлы нельзя. Для создания файла родительский каталог должен существовать; создать каталог можно разрешённой shell-командой.
- `/undo` восстанавливает только правки файловых инструментов. Изменения, сделанные shell, он не отменяет. При последующих правках пользователя или shell отмена остановится с конфликтом, сохранив текущие файлы. Автоматических Git-коммитов нет.
- Лимиты вывода и контекста явные. При заполнении контекста используйте `/compact` или новую сессию. Сжатие старой истории может потерять детали.
- Поддерживаются текстовые модели с function calling. Vision, MCP и плагины пока не реализованы. Дополнительные требования отдельных моделей к истории reasoning могут ограничивать совместимость.
- Адаптеры провайдеров проверяются на локальных HTTP/TLS-серверах. Живые проверки проводились через Yandex, OpenRouter и GigaChat; они подтверждают конкретные сценарии, а не качество работы всех моделей.

## Разработка

```sh
cargo fmt --all --check
cargo clippy --all-targets -- -D warnings
cargo test --all-targets
cargo build --release --locked
```

Тесты не требуют платных API: используют временные проекты и локальные серверы. На Linux/macOS сквозная проверка интерфейса использует Python 3 из стандартной поставки CI: настоящий PTY с моделью VT-сетки, координаты футера и курсора, меню, вставку текста, streaming, прокрутку, resize, разрешения и отмену запроса. TLS-тест использует `openssl`, если он установлен. CI запускает проверки на Linux, macOS и Windows. На Unix отмена shell завершает группу процессов; на Windows пока завершается только непосредственный дочерний процесс.

Живые E2E используют сохранённые ключи и расходуют токены, поэтому по умолчанию пропускаются. Они проверяют создание Godot-проекта вне рабочей папки с загрузкой настоящей сцены (Yandex и GigaChat) и делегирование файловых правок двум worker (Yandex). Oracle проверяет загрузку сцены и ошибки движка; игровой процесс и управление требуют отдельной проверки. Результат зависит от выбранной модели. Нужен Godot 4 в PATH либо путь в `RCODE_GODOT_BIN`:

```sh
cargo test --test live_yandex yandex_ -- --ignored --test-threads=1 --nocapture
# Проверить другую модель в том же Yandex API без изменения своих настроек:
RCODE_LIVE_YANDEX_MODEL=deepseek-v4.1-flash/latest cargo test --test live_yandex yandex_ -- --ignored --test-threads=1 --nocapture
RCODE_LIVE_GIGACHAT_MODEL=GigaChat-3-Ultra cargo test --test live_yandex gigachat_ -- --ignored --nocapture
```
