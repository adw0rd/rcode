# Выравнивание задания TODO API и HTTP oracle

## Контекст

Live-прогон GigaChat завершился со статусом `failed`, потому что независимый `http-crud-contract` не прошёл. На сохранённом snapshot oracle воспроизводимо останавливается после 10 секунд ожидания health-check. При этом задание не требует endpoint `/health`, который oracle проверяет первым.

Дополнительные запросы к snapshot подтвердили ошибки самого сгенерированного API: принятие `completed: null`, неверные статусы для явного `null`, проверку длины title до trim и возврат `400` там, где oracle ожидает `422`. Эти результаты сохраняются как материал сравнения модели и не исправляются в артефакте.

## Решение

Выровнять видимое задание под существующий строгий oracle. Не ослаблять проверки и не менять сгенерированные snapshots или прошлые reports.

В `evals/todo-api/cases/todo-api/task.md` явно указать:

- `GET /health` возвращает статус 200 и ровно JSON `{"status":"ok"}`;
- отсутствующий при POST title и title с длиной после trim вне диапазона 1–200 возвращают 422;
- невалидный title при PATCH возвращает 422;
- явный `null` для title или completed по-прежнему возвращает 400;
- пустой PATCH по-прежнему возвращает 400.

Изменение документирует уже существующие проверки и не добавляет новых требований к oracle.

## Regression test

В `tests/eval_todo_controls.py` добавить host-only тест, который проверяет, что задание содержит явные формулировки health-check и статусов 422. До изменения `task.md` тест должен падать, после — проходить. Существующий тест продолжит проверять идентичность встроенного oracle-скрипта и `check_api.py`.

## Проверка

1. Запустить новый contract test до исправления и зафиксировать RED.
2. Обновить задание и получить GREEN.
3. Запустить все TODO controls, включая отрицательный и исправленный Docker fixtures.
4. Запустить общий eval controls corpus, host tests и `rcode eval validate --suite evals/todo-api/manifest.json`.
5. Выполнить стандартные проверки проекта для итоговой ветки.
6. После публикации изменения выполнить новые GigaChat и Qwen live-прогоны на одной версии suite с diagnostics и сравнить только эти свежие reports: изменится hash задания, поэтому старый GigaChat report не является непосредственно сопоставимым baseline.

## Ограничения

- `evals/todo-api/oracles/check_api.py`, встроенный oracle JSON и positive control не меняются.
- Код GigaChat в `artifacts/` не исправляется и не публикуется.
- Дефекты преобразования неподдерживаемых типов, которые oracle не проверяет, не добавляются в эту задачу.
- Live-прогоны отличаются от локальных Docker controls и не заменяются ими.
