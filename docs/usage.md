# Руководство rcode

## Подключение и диагностика

```sh
rcode connect gigachat
rcode models --provider gigachat
rcode doctor
rcode doctor --check --provider gigachat
```

`doctor` показывает каталог данных и источник ключа без его значения. `--check` обращается к API. Явный CA-файл задаётся через `rcode --ca-file /path/to/ca.pem connect gigachat`; проверка TLS остаётся включённой.

Переменные окружения имеют приоритет над сохранённым ключом:

| Провайдер | Переменные |
| --- | --- |
| Yandex | `RCODE_YANDEX_API_KEY`, `YANDEX_API_KEY` |
| GigaChat | `RCODE_GIGACHAT_AUTH_KEY`, `GIGACHAT_AUTH_KEY`, `GIGACHAT_CREDENTIALS` |
| OpenRouter | `RCODE_OPENROUTER_API_KEY`, `OPENROUTER_API_KEY` |
| Свой API | `RCODE_CUSTOM_API_KEY`, `OPENAI_API_KEY` |

Ключ локального сервера из окружения не читается: см. раздел «Локальная модель».

Модель выбирается через `/model`, провайдер — через `/provider`. Последняя выбранная модель каждого провайдера стоит первой и выделена; Enter принимает её, сохраняя effort. Меню `/effort` показывает поддерживаемые моделью уровни. rcode не переключает провайдера самостоятельно.

В полноэкранном режиме Shift+Enter вставляет новую строку, Enter отправляет запрос. Для Shift+Enter нужен терминал с поддержкой расширенного протокола клавиатуры, например cmux или Ghostty. В остальных терминалах используйте Alt+Enter или Ctrl+J.

## Локальная модель

Провайдер `local` работает с OpenAI-совместимым сервером, который вы запустили на этом компьютере: Ollama, llama.cpp (`llama-server`), MLX или LM Studio. rcode не запускает сервер, не скачивает модели и не меняет контекст сервера.

```sh
rcode local discover [--json]
rcode local add ИМЯ --base-url http://127.0.0.1:ПОРТ/v1 [--runtime ollama|llamacpp|mlx|lmstudio|openai]
                [--model ID] [--context-tokens N] [--max-output-tokens N] [--vision]
                [--thinking on|off] [--api-key-stdin] [--activate] [--force]
rcode local list [--json]
rcode local use ИМЯ [--model ID]
rcode local key ИМЯ (--stdin | --delete)
rcode local remove ИМЯ
rcode models --profile ИМЯ
rcode doctor [--check] --profile ИМЯ
rcode exec --profile ИМЯ 'запрос'
```

`--profile` подразумевает `--provider local`; вместе с другим `--provider` это ошибка. Без `--model` команда `add` берёт первую чат-модель из `/models` сервера. `discover` проверяет только 127.0.0.1:11434, :8080 и :1234 с коротким таймаутом. В интерактиве `/provider` → `local` открывает список профилей, поиск серверов и ввод адреса вручную; `/model` показывает модели сервера активного профиля.

Ключ сервера необязателен. Если он задан, то должен быть не короче 8 символов; более короткий ключ не принимается ни при сохранении, ни при чтении из `credentials.json`. Его можно передать только через stdin или скрытый ввод; ключ хранится в `credentials.json` под именем профиля и удаляется вместе с профилем. Ключ отправляется только на адрес, для которого он сохранён: другой порт, `127.0.0.2` или `::1` считаются другими серверами, `localhost` — это `127.0.0.1`. Если адрес профиля изменился, восстановленная сессия с ключом не продолжится, пока профиль не выбран заново. Прокси и перенаправления для локальных серверов не используются.

Бюджет контекста local считается в оценочных токенах: контекст профиля минус ответ и резерв, включая системный промпт и описания инструментов. Фактический контекст сервера rcode читает, только когда сервер его сообщает: у llama.cpp — из `/props`, если там есть эти метаданные; у Ollama — из `/api/ps`, только для уже загруженной модели. Если он меньше профиля, бюджет уменьшается и выводится предупреждение. У MLX, LM Studio и `openai` используется значение профиля. `--context-tokens` не меняет контекст сервера: если указать больше, чем реально настроено на сервере, сервер может усечь запрос, и rcode это не обнаружит. `doctor` сообщает `context_source`: `profile` или `runtime`. Перед переполнением история сокращается автоматически.

В одном процессе rcode одновременно идёт одна генерация на порт сервера, включая субагентов и разные профили одного сервера. Два отдельно запущенных rcode эту очередь не делят и могут генерировать на одном сервере параллельно. Отмена освобождает очередь rcode; сервер может ещё доделывать прерванный ответ.

Рассуждения модели в полях `reasoning_content` и `reasoning`, а также ведущий блок `<think>` не показываются, не сохраняются и не отправляются обратно. Если шаблон модели сам открывает `<think>` и в ответ приходит только закрывающий `</think>`, без `--thinking` rcode распознаёт его лишь в первых 1024 байтах ответа и только для MLX и `openai`; более длинное рассуждение такой модели будет показано и сохранено как ответ. Для моделей, которые думают всегда (например, `*-Thinking`), укажите `--thinking on`: rcode дождётся `</think>` (если тега нет, ответ появится целиком в конце, без потерь) и передаст серверу `chat_template_kwargs.enable_thinking`. `--thinking off` передаёт `false`. Этот параметр учитывается, только если сервер и шаблон модели его поддерживают; для Ollama `--thinking` не принимается. Effort для local всегда `auto`.

Вызов инструментов зависит от модели и сервера. Если сервер вернул вызов инструмента текстом или отклонил `tools`, rcode покажет ошибку и не будет повторять запрос без инструментов; для llama.cpp запускайте сервер с `--jinja`. Изображения отправляются только профилям с `--vision`. Баланс для local не применяется.

## Обновление

```sh
brew update
brew upgrade adw0rd/tap/rcode
rcode --version
```

После обновления перезапустите работающий rcode. Настройки и сохранённые сессии остаются на месте; нужный диалог можно продолжить через `rcode --resume ID_СЕССИИ`.

Если версия не изменилась, проверьте, какой бинарник запускается. На macOS/Linux команда `command -v rcode` покажет путь: установки через Cargo и Homebrew могут находиться в разных каталогах. Номер версии также виден справа в футере.

## Баланс провайдера

В футере показан баланс активного провайдера. Он обновляется в фоне раз в минуту; `/balance` обновляет данные сразу и показывает подробности. Из обычного терминала: `rcode balance --provider openrouter`; для автоматизации добавьте `--json`.

В меню `/provider` подключённые OpenRouter и GigaChat показывают баланс в скобках. В полноэкранном режиме данные загружаются в фоне, поиск и выбор остаются доступны; выход из меню отменяет незавершённые запросы. В `--plain` загрузка баланса перед списком занимает до 8 секунд; Ctrl+C прерывает ожидание. Для GigaChat показывается пакет последней выбранной у этого провайдера модели. Если API не предоставляет баланс или запрос завершился ошибкой, меню сообщает об этом без подстановки суммы.

- **OpenRouter:** остаток денег на счёте и отдельный лимит API-ключа. Если API не разрешает читать баланс счёта, rcode показывает доступный остаток лимита ключа с явной подписью. Отсутствие лимита ключа не означает неограниченный баланс счёта. [API OpenRouter](https://openrouter.ai/docs/api/api-reference/credits/get-remaining-credits).
- **GigaChat:** остатки оплаченных пакетов в токенах, в футере — пакет выбранного семейства моделей. При pay-as-you-go API баланса пакетов недоступен. [Документация GigaChat](https://developers.sber.ru/docs/ru/gigachat/guides/using-sdks).
- **Yandex:** обычный ключ AI Studio не даёт доступ к Billing API; нужен отдельный IAM-доступ. `/balance` показывает пояснение и ссылку в кабинет.
- **Свой OpenAI API:** стандартного метода баланса нет; rcode не отправляет запросы к неизвестным платёжным endpoint.

При сетевой ошибке последнее полученное значение помечается `устар.`. Пока данные не получены, число не подставляется. На узком экране баланс может скрываться; подробности доступны через `/balance`. Фоновые данные и `/balance` не добавляются в переписку с моделью.

Можно спросить агента: «Какой сейчас баланс?» Он проверит текущего провайдера инструментом `get_provider_balance` и ответит по свежим данным. Результат такого явного вызова передаётся выбранной модели и сохраняется в диалоге, включая экспорт. Ключи остаются внутри rcode. `/balance` — команда интерфейса; выполнять её через shell не нужно.

## Одна задача и автоматизация

```sh
rcode exec "Изучи проект и объясни точку входа"
rcode exec --approval-mode auto-edit "Исправь ошибку в обработке дат"
rcode exec --approval-mode auto-edit --allow-shell "Исправь ошибку и проверь тесты"
rcode exec --plan "Составь план обновления зависимостей"
rcode exec --json --max-steps 20 "Найди причину ошибки"
```

В `exec` без терминала действия, требующие подтверждения, отклоняются. `--allow-shell` разрешает команды явно; в `full-access` этот флаг не требуется. JSONL содержит только версионированные события, без ANSI.

Коды завершения: `0` — ход завершён; `1` — незавершённое действие или лимит; `2` — настройки/аргументы; `3` — авторизация API; `4` — транспорт/протокол API; `130` — прерывание. Окончание хода не гарантирует правильность кода: проверяйте diff и результат работы.

## Файлы и внешние каталоги

`AGENTS.md` в корне проекта задаёт инструкции агенту. Файловые инструменты учитывают Git ignore и блокируют `.git`, распространённые секретные файлы и symlink. Перед перезаписью существующего файла агент читает его: rcode проверяет, что содержимое после чтения не изменилось.

```sh
rcode -C /path/to/project --add-dir /tmp/example
```

Внешний путь можно разрешить и в ходе работы. В `full-access` такие каталоги подключаются автоматически. `/undo` отклоняется при конфликте с последующими изменениями пользователя и сохраняет текущие файлы.

## Ручные команды

```text
!git status
!python -m pytest -q
!cd src && pwd
```

Маркер `!` красный. Команда выполняется без обращения к модели; stdout/stderr и код завершения сохраняются в диалоге. Каждый запуск использует отдельный неинтерактивный shell из папки проекта, с таймаутом 300 секунд и ограничением вывода 64 КиБ. Изменения `cd` и переменных не переносятся между командами. Ключи провайдера не наследуются в окружение shell.

На Unix отмена завершает группу процессов команды; на Windows — непосредственный дочерний процесс.

## Изображения

Вставьте путь к PNG/JPEG/TIFF или отправьте запрос с подписью:

```text
/attach "/tmp/мой скрин.tiff" Объясни ошибку
```

Изображение передаётся выбранной модели. rcode принимает PNG/JPEG до 10 МиБ и исходный TIFF до 64 МиБ. Первая страница TIFF автоматически преобразуется в PNG; исходник остаётся без изменений. Пределы декодирования TIFF: 16 миллионов пикселей, 16384 по стороне, бюджет декодера 128 МиБ; готовый PNG — до 10 МиБ. До 10 изображений могут входить в контекст запроса. Неподдерживаемый формат вызывает локальную ошибку.

Копия вложения сохраняется в сессии, поэтому `/resume` работает после удаления временного исходника. GigaChat использует Files API; после перезапуска копия загружается заново при следующем запросе. Markdown-экспорт включает имена и размеры вложений, без их байтов.

## Сессии, контекст и экспорт

```sh
rcode sessions
rcode --resume ID_СЕССИИ
rcode --resume latest --compact exec "Продолжи работу"
```

Внутри CLI доступны `/resume`, `/new`, `/clear`, `/compact`, `/context`, `/status`, `/cost` и `/export`. `/new` и `/clear` начинают новый диалог, сохраняя историю ввода проекта.

История ввода содержит до 1000 записей на проект, не более 2 МиБ текста. Ctrl+P/N работают с многострочным вводом; в пустом однострочном поле доступны также ↑/↓. Известные API-ключи в истории маскируются.

Перед новым запросом, между шагами и сразу после восстановления rcode проверяет локальный бюджет контекста. Для облачных провайдеров с 150 000 символов включается автокомпакт с целью около 110 000. Текущий запрос и важные результаты сохраняются, старые сообщения заменяются неполными выдержками. Выполненные действия не повторяются. Локальный бюджет резервирует 8192 символа на изображение; фактические токены показывает API.

`/export` создаёт новый Markdown-файл в проекте; можно указать `/export "/tmp/диалог.md"`. Экспорт не перезаписывает файлы, маскирует известные ключи и отмечает неполноту сокращённой истории.

## Субагенты

Попросите делегировать независимые части задачи обычным текстом. `explorer` исследует проект, `reviewer` проверяет код, `worker` выполняет изменения. У каждого отдельный контекст с тем же выбранным провайдером и моделью. Доступны до трёх одновременных субагентов и шести запусков за ход.

Исследователь и ревьюер работают только на чтение; исполнитель использует разрешения основного агента. Режим плана ограничивает всех чтением. `/agents` показывает задачи и результаты; `/agents ID` открывает подробности. Токены дочерних запросов входят в расход сессии. Отмена останавливает дочерние задачи, восстановление не запускает их заново.

## Хранение и ограничения

`RCODE_HOME` меняет каталог данных; он должен находиться вне проекта. Указание нового каталога не переносит старые данные автоматически. Настройки находятся в `config.json`, ключи — в `credentials.json`, разрешения проектов — в `permissions.json`, сессии — в `sessions/`, история ввода — в `input-history/`. Сохраните весь каталог для резервной копии.

Ожидание заголовков генерации задаётся `request_timeout_secs` (по умолчанию 300), пауза между частями ответа — `idle_timeout_secs` (90). После таймаута запрос автоматически не повторяется. Эти поля находятся в секции провайдера `config.json`.

Один ход по умолчанию ограничен 32 запросами к модели, `--max-steps` допускает до 256. При повторяющейся одинаковой ошибке записи агент получает подсказку, затем бесполезный цикл останавливается.

rcode — ранняя версия локального агента. ОС-песочницы, MCP и плагинов пока нет. Дополнительные требования отдельных моделей к reasoning-истории могут ограничивать совместимость.
